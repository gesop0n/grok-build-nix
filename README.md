# grok-build-nix

[![Build](https://github.com/gesop0n/grok-build-nix/actions/workflows/build.yml/badge.svg)](https://github.com/gesop0n/grok-build-nix/actions/workflows/build.yml)
[![Update Grok](https://github.com/gesop0n/grok-build-nix/actions/workflows/update.yml/badge.svg)](https://github.com/gesop0n/grok-build-nix/actions/workflows/update.yml)

A Nix flake that packages [**Grok Build**](https://github.com/xai-org/grok-build) — xAI's
terminal coding agent — as a reproducible, pinned derivation.

Upstream ships through `curl -fsSL https://x.ai/cli/install.sh | bash`, which drops an
unpinned, self-updating binary into `~/.grok/bin`. This flake pins an exact version with
verified hashes instead, so your machines are declarative and reproducible.

## Quick start

```bash
nix run github:gesop0n/grok-build-nix
```

Then authenticate once with `grok login` (or set `GROK_DEPLOYMENT_KEY` for enterprise
deployments) and start a session:

```bash
cd your-project
grok                                  # interactive TUI
grok -p "explain this repo's architecture"   # headless, single turn
```

## Installation

### Flake input

```nix
{
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixpkgs-unstable";

    grok-build-nix = {
      url = "github:gesop0n/grok-build-nix";
      inputs.nixpkgs.follows = "nixpkgs";
    };
  };
}
```

Pin a specific release by tag when you want updates to be an explicit action:

```nix
grok-build-nix.url = "github:gesop0n/grok-build-nix/v1.0.34";
```

### Home Manager

```nix
{ inputs, pkgs, ... }:
{
  home.packages = [
    inputs.grok-build-nix.packages.${pkgs.system}.default
  ];
}
```

### NixOS / nix-darwin

```nix
{ inputs, pkgs, ... }:
{
  environment.systemPackages = [
    inputs.grok-build-nix.packages.${pkgs.system}.default
  ];
}
```

### Overlay

Use the overlay when you would rather refer to `pkgs.grok` everywhere:

```nix
{
  nixpkgs.overlays = [ inputs.grok-build-nix.overlays.default ];
  environment.systemPackages = [ pkgs.grok ];
}
```

### Imperative

```bash
nix profile install github:gesop0n/grok-build-nix
```

## Supported platforms

| Nix system       | Upstream artifact | Flake output            |
| ---------------- | ----------------- | ----------------------- |
| `aarch64-darwin` | `macos-aarch64`   | yes                     |
| `aarch64-linux`  | `linux-aarch64`   | yes                     |
| `x86_64-linux`   | `linux-x86_64`    | yes                     |
| `x86_64-darwin`  | `macos-x86_64`    | overlay only (see below)|

Nixpkgs 26.11 dropped `x86_64-darwin`, so this flake cannot expose a per-system output for
Intel Macs — that output would not even evaluate. The derivation itself still supports the
platform, so if you pin nixpkgs 26.05 you can still get it through `overlays.default` as
`pkgs.grok`. `sources.json` keeps the `x86_64-darwin` hash current for exactly that case.

Upstream publishes Windows builds too, which Nix does not target.

## What the package does

- **Fetches the official release binary** for the host platform from `https://x.ai/cli`,
  with the upstream GCS bucket as a mirror, verified against the hashes in
  [`sources.json`](sources.json).
- **Disables the built-in auto-updater** by setting `GROK_DISABLE_AUTOUPDATER=1` in the
  wrapper. The Nix store is read-only, so a self-update could never succeed; updates come
  from this flake instead. `grok update` still reports what upstream has available.
- **Installs bash, zsh, and fish completions**, generated by running `grok completions`
  at build time.
- **Leaves the binary untouched.** Linux builds are static-pie and Darwin builds are
  signed Mach-O, so `dontPatchELF` and `dontStrip` are both set — the fixup phase would
  otherwise corrupt them. The real executable lives in `libexec/grok` and keeps its
  basename, because Grok re-execs itself when switching screen modes.
- **Checks itself at build time.** `installCheckPhase` runs `grok --version` and asserts
  it matches the pinned version.

## Package options

Override them like any other nixpkgs derivation:

```nix
inputs.grok-build-nix.packages.${pkgs.system}.default.override {
  withAgentAlias = true;
}
```

| Option                   | Default                | Description                                                                                          |
| ------------------------ | ---------------------- | ---------------------------------------------------------------------------------------------------- |
| `withAgentAlias`         | `false`                | Also link the binary as `agent`, the way upstream's installer does. Off by default because `agent` collides easily on `PATH`. Also exposed as the `grok-with-agent-alias` package. |
| `disableAutoUpdater`     | `true`                 | Set `GROK_DISABLE_AUTOUPDATER=1` in the wrapper.                                                      |
| `installShellCompletions`| native builds only      | Generate shell completions. Requires executing the built binary, so it is off when cross-compiling.  |
| `sources`                | `./sources.json`       | Release metadata. Point it at your own JSON to pin a different version or channel.                   |

## Updating

The pin lives in a single file, [`sources.json`](sources.json):

```json
{
  "channel": "stable",
  "version": "1.0.34",
  "platforms": {
    "aarch64-darwin": { "artifact": "macos-aarch64", "hash": "sha256-..." }
  }
}
```

[`scripts/update.sh`](scripts/update.sh) rewrites it: it resolves the channel pointer,
re-prefetches every platform hash, and verifies that the result still builds — restoring
the previous pin if anything fails.

```bash
./scripts/update.sh                  # follow the channel to its latest release
./scripts/update.sh --check          # exits 1 when an update is available, 2 on error
./scripts/update.sh --version 1.0.34 # pin an exact version
./scripts/update.sh --channel alpha  # switch channels (stable | alpha | enterprise)
```

The [Update Grok](.github/workflows/update.yml) workflow runs this hourly and, when upstream
moves, opens a pull request and merges it once `nix build` passes on `x86_64-linux`.
[Build](.github/workflows/build.yml) then builds and tests every supported platform on `main`,
and [Tag Release](.github/workflows/tag.yml) tags `main` with `v<version>` plus a moving
`latest`.

## Repository layout

```
.
├── flake.nix                 # outputs: packages, apps, checks, devShell, overlay
├── package.nix               # the derivation
├── sources.json              # the pin: channel, version, per-platform hashes
├── scripts/update.sh         # rewrites sources.json and verifies the build
└── .github/workflows/
    ├── build.yml             # build + test on every supported platform, flake check
    ├── update.yml            # hourly upstream check, opens and merges a PR
    └── tag.yml               # tags main with the pinned version
```

## Development

```bash
nix develop           # cachix, jq, nix-prefetch, nixfmt, shellcheck
nix build .#grok      # build for the current system
nix flake check       # evaluate and build the checks
nix flake check --all-systems   # evaluate every system, not just this one
nix fmt               # format the Nix files
```

### Optional: binary cache

CI pushes to [Cachix](https://cachix.org) when a `CACHIX_AUTH_TOKEN` secret is present,
and skips those steps otherwise. To enable it, create a cache, then set the repository
secret `CACHIX_AUTH_TOKEN` and (if the name differs from `grok-build`) the repository
variable `CACHIX_CACHE`.

Consumers opt in through their Nix configuration:

```nix
nix.settings = {
  substituters = [ "https://grok-build.cachix.org" ];
  trusted-public-keys = [ "grok-build.cachix.org-1:..." ];
};
```
